Overview

Each "client" is one business running its own private copy of the app — its own database, its own login, its own web address (like acme.yourdomain.com). They share the same server, but nothing they do can be seen by another client. This page is where you create, update, and manage all of them from one place.

Updating the app (putting new code live)

When the app's code changes — a bug fix, a new feature — you don't touch anything technical. Just go to Clients and click Update all apps at the top. A window opens and walks through three steps automatically:

  1. Downloading update & building — the new version is fetched and prepared. Nobody is affected yet; every client keeps working normally.
  2. Applying update — the new version goes live for every client. This is the only moment with any interruption, and it's brief (about a minute).
  3. Done — you'll see a status line for every client confirming it came back up healthy.

If step 1 fails for any reason, nothing changes — every client just keeps running the version it had before. You can safely click it again once the issue is fixed.

Each client also has its own Rebuild web button (on its row in Clients). That one only refreshes that single client's look-and-feel (name, colors, logo) — it does not push new app code. For an actual code update, always use Update all apps.

Adding a new client

On the Clients page, fill in the "Add a client" form:

  • Subdomain — the short name in their web address, e.g. acme becomes acme.yourdomain.com. Lowercase, no spaces.
  • Business type — pick the version of the app that matches what they sell (food & beverage vs. logistics/wholesale).
  • Superadmin password — this is the login you'll hand to that client's owner/manager. Keep a copy somewhere safe; it isn't shown again.
  • Test tenant — only check this for a rehearsal/demo account, never a real paying client. It unlocks the Test Lab tools, which are too heavy and risky to ever run against a live client by accident.

Creating a client takes a few minutes (it's building their private copy of the app from scratch). Once done, their link appears on the Clients page.

Managing an existing client

Each row on the Clients page has:

  • Resources — raise or lower how much memory/CPU priority that client gets, if they're growing or you're consolidating.
  • Stop / Start — temporarily take a client offline (e.g. non-paying, or maintenance) without deleting anything.
  • Logs — a live technical readout of what that client's app has been doing. Mostly useful when troubleshooting with support.
  • Wipe data (red) — erases that client's orders/inventory/history but keeps their login and settings. Irreversible.
  • Delete (red) — removes the client entirely: their app, their data, their web address. Irreversible.

Both red actions ask you to type the client's name and a second password to confirm, specifically so they can't happen by accident.

Billing

The Billing page is a simple paid/unpaid tracker, one row per client, reset every calendar month. It does not charge anyone or move any money — you still collect payment however you normally do (bank transfer, e-wallet, cash), and just click Mark Paid here once you've confirmed it landed. Set a monthly fee per client so you have a number to check against; it's just a note for you, not something enforced automatically.

Test Lab

A safe place to hammer a test client with fake orders and simulated traffic, to see how the system holds up before something similar happens for real. It only ever runs against clients explicitly flagged "Test tenant" when created — it will refuse to run against a real client, even if you try.

Errors & logs

The Errors page collects anything that went wrong across every client in one place, so you don't have to check each one individually. Logs (on a client's row) is the raw technical output from that client's app — useful mostly when working with support to diagnose something specific.

If something looks broken

  • A client shows "unhealthy" or won't load — try Stop then Start on that row first.
  • After clicking Update all apps, a client shows an error in the results — the others are unaffected; check that client's Logs, or retry the update.
  • You're logged out unexpectedly — sessions last 8 hours; just sign in again.
  • Still stuck — this panel is reached over a private connection (SSH tunnel), so whoever set that up for you is the right person to loop in.

Update all apps

This rebuilds every client's app to the latest version. The build runs first with no interruption; then each app restarts briefly (about a minute total) while the update is applied.
